# 里程碑

> 排期假设 1 人全职开发。每个阶段有明确的"通过条件"，不通过不进入下一阶段。

## 阶段 0：风格分析 Spike（第 1 周）

**目标**：验证产品心脏——LLM 能否从对话中稳定产出用户认可的风格卡。

**做法**：
1. 写一个独立 Go 脚本（或直接在 backend 里加个 cmd），不做产品架子
2. 构造/收集 10-20 段风格差异明显的对话样本（可让 LLM 生成模拟对话，或用自己与朋友的聊天记录脱敏）
3. 用风格分析 Prompt 跑批，人工评估：输出稳定性（同输入多跑几次结果是否一致）、JSON 合法率、维度区分度
4. 自测：分析自己的对话，看风格卡是否"像自己"

**通过条件**：JSON 合法率 > 95%；同一用户多次分析结果关键维度一致；自己认可风格卡描述。
**不通过**：回到 Prompt 与维度设计迭代，仍不行则重新评估"对话提取画像"可行性——这是止损点。

## 阶段 1：单边 MVP（第 2-5 周）

- 后端骨架：Gin + PostgreSQL + 迁移 + 部署脚本
- 用户系统（设备匿名登录）、JWT
- AI 聊天（同步接口 + LLM Provider 接口 + 会话记忆）
- 异步风格分析 worker + 风格卡 CRUD
- 前端骨架：Vue 3 + H5 聊天界面 + 风格卡页面

**通过条件**：真机 H5 上完整走通"注册 → 聊天 → 收到风格卡就绪通知 → 查看/编辑/删除"。

## 阶段 2：匹配与契合提示（第 6-8 周）

- 匹配池 opt-in
- 向量化代码（风格卡 → 64 维）+ pgvector
- 匹配打分 + 契合提示接口
- 真人接触请求 / 同意 / 拒绝
- 真人一对一文本聊天（短轮询）
- 同意/撤回/举报/拉黑 + AI 标识

**通过条件**：两个测试账号完整走通"opt-in → 收到契合提示 → 发起接触 → 双方同意 → 真人聊天"。

## 阶段 3：内测上线（第 9-10 周）

- 内容审核接入（规则引擎起步）
- 速率限制、日志、监控告警
- 部署上线，邀请 20-50 个种子用户

**通过条件**：稳定运行一周；收集到风格卡认同率、7 日留存的首批真实数据。

## 阶段 4：P1 迭代（内测数据驱动）

按内测数据决定优先级：AI 暖场、聊后反馈、语音、付费。

## 关键验收指标（目标值，可调）

| 指标 | 目标 |
|---|---|
| 风格卡认同率（用户觉得"像自己"） | > 60% |
| 7 日留存 | > 25% |
| 契合提示点击率 | > 15% |
| 接触请求 → 真人对话转化 | > 20% |
| 举报率 | < 1% |
| 撤回授权后数据停止用于匹配 | ≤ 24h |
